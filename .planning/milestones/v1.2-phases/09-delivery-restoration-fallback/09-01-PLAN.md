<objective>
Make outbound email dependable again: (1) DLVR-01 — restore a working
provider so invites, the RESP-02 nudge, and confirmation/finalization emails
actually dispatch in production instead of the current copy-link-only accepted
limitation; and (2) DLVR-02 — add a fallback provider behind the SAME
`sendEmail()` seam so a single provider outage, rate-limit, or misconfig degrades
to a backup rather than to nothing.

The code change is confined to the one transport seam (`src/lib/email/send.ts`)
and its env declaration (`src/lib/env.ts`): refactor the single-provider branch
into an ordered primary→fallback chain that preserves every load-bearing
invariant (never throws, no-secret-leak, single-string `to`, `none`→"not
configured", zero-email-env still builds). No call site changes — the chain is
invisible above the seam.

DLVR-01's "sends in production" is inherently config/credential-gated: the code
path already exists and is tested (Phase 4), so the restore is (a) diagnosing
why prod email is currently off, (b) Dave supplying working provider creds as
Vercel env (user_setup), and (c) a gated redeploy. The prod INBOX / not-spam
human check is DELIBERATELY forwarded to Phase 10 (DLVR-03) — it is not
re-counted here.

Output: a fallback-capable `sendEmail()` with full unit coverage, an optional
`EMAIL_FALLBACK_PROVIDER` env, a written diagnosis of the current prod email
state, and a gated prod restore.
</objective>
